# Архитектура

Монорепозиторий разделён на `apps/api` и `apps/mobile`. API — единственный авторитет для сумм, состояния, долговой стратегии и главного действия. Все user-scoped запросы включают `user_id` в SQL-фильтр; UUID из тела не назначают владельца.

Mobile получает реальные данные через Dio. Последний план хранится локально, а операции при сетевой ошибке попадают в очередь с постоянным idempotency key. Серверная уникальность `(user_id, idempotency_key)` защищает от дублей. При конфликте валюта/владелец отклоняются, а не перезаписываются.

Fake AI реализует тот же интерфейс, что внешний provider. Ответ проходит строгую Pydantic-схему; после двух ограниченных попыток возвращается детерминированный fallback. Суммы из AI никогда не попадают обратно в модель.
